# Tesla 한글 매뉴얼로 KoGPT2 파인튜닝하기 — 그리고 왜 안 됐는지

테슬라 4개 차종(Model S / 3 / X / Y)의 한글 소유자 매뉴얼 PDF에서
Q&A 데이터셋을 만들고, `skt/kogpt2-base-v2`(125M)를 노트북 GPU
(**MX450, VRAM 2GB**)에서 파인튜닝한 기록이다.

**결론부터:** 매뉴얼체 문장은 학습됐지만 **지식은 학습되지 않았다.**
데이터를 4배로 늘리고, 15,596곳을 정제하고, 범위를 좁히고, 에폭을 늘려도
정확도는 오르지 않았다. 원인을 분리해보니 데이터 문제가 아니라 **모델 용량 문제**였다.

---

## 1. 무엇을 했나

| 단계 | 스크립트 | 결과 |
|---|---|---|
| 1. PDF → 텍스트 | `01_fetch_manual.py` | 4개 PDF(59MB) → 구역·문단 단위 텍스트 |
| 1-b. 텍스트 정제 | `fix_text.py` | 줄바꿈으로 쪼개진 단어 **15,596곳** 복원 |
| 2. 조각내기 | `02_make_dataset_batch.py chunk` | 1,200자 단위 **조각 1,527개** |
| 2-b. Q&A 생성 | `02_make_dataset_batch.py` (OpenAI Batch API) | **4,929쌍** (v1 5,771쌍에서 재생성) |
| 3. 파인튜닝 | `03_train.py` | 전체 파라미터 학습, **최대 VRAM 2.01GB** |
| 4. 평가 | `chat_test.py`, `eval_ckpt.py` | 32문항 수동 평가셋 + 자동 지표 |

2GB VRAM에 125M 전체 학습을 올리기 위해 **`adafactor` 옵티마이저**를 썼다.
Adam의 옵티마이저 상태가 약 1.0GB라 그대로는 OOM이 난다.

```bash
python 03_train.py --model skt/kogpt2-base-v2 --data data/qa_all.jsonl \
       --out runs/tesla_v2 --epochs 2 --bs 4 --grad-accum 4 --optim adafactor
```

## 2. 결과 — 여섯 번 학습했고 전부 같은 결론이 나왔다

| 실험 | 데이터 | 에폭 | test 손실 | 생성 F1 | 되풀이 기준선 | F1 − 기준선 |
|---|---|---|---|---|---|---|
| 이전 프로젝트 (Model Y만) | 1,441쌍 | 2 | 2.930 | 0.232 | 0.233 | −0.001 |
| ① 4차종 v1 | 5,771쌍 | 2 | 2.141 | 0.239 | 0.238 | **+0.001** |
| ② 4차종 v1 · 에폭 ↑ | 5,771쌍 | 4 | **1.928** | 0.224 | 0.238 | −0.014 |
| ③ 4차종 v2 (정제) | 4,929쌍 | 2 | 2.142 | 0.256 | 0.298 | −0.042 |
| ④ 안전주제 v1 | 389쌍 | 4 | 2.128 | 0.231 | 0.261 | −0.030 |
| ⑤ 안전주제 v2 | 225쌍 | 8 | 2.877 | 0.196 | 0.251 | −0.056 |

> **되풀이 기준선(echo baseline)**: 질문을 그대로 답으로 되풀이했을 때 나오는 F1.
> 이걸 못 넘으면 학습한 모델이 "질문 복사기"보다 못하다는 뜻이다.

**여섯 번 중 기준선을 넘은 건 한 번, 그것도 +0.001이다.**

손실은 2.930 → 1.928로 34% 내려갔고 퍼플렉서티는 18.7 → 6.9로 떨어졌지만,
생성 F1은 0.232 → 0.224로 제자리였다. **손실과 생성 품질이 반대로 갔다.**

## 3. 핵심 발견 — 지표에 속았다

안전 주제만 추려 학습했을 때 **수치 재현율이 0.214 → 0.429로 2배** 뛰었다.
"드디어 숫자를 외웠구나" 했는데, `test_preds.jsonl`을 열어
정답 숫자를 하나하나 추적해보니 결과가 이랬다.

```
[tesla_ep4]   정답 숫자 22개 중  베낀 것 1 / 진짜 외운 것 0 / 못 꺼낸 것 21
[tesla_v2]    정답 숫자  9개 중  베낀 것 1 / 진짜 외운 것 0 / 못 꺼낸 것  8
[safety_v2]   정답 숫자  8개 중  베낀 것 4 / 진짜 외운 것 0 / 못 꺼낸 것  4
```

**세 모델 합쳐 정답 숫자 39개. 진짜 외운 것은 0개였다.**

수치 재현율 0.429는 전부 **질문에 이미 있던 숫자를 그대로 베낀 것**이었다.
이 지표는 "답변에 정답 숫자가 있는가"만 보고 **그 숫자가 어디서 왔는지는 보지 않는다.**

> 질문이 "**72시간** 이내에 충전해야 합니까?"이면
> 답변에 "72시간"만 들어가도 점수가 올라간다. 베꼈는지 외웠는지 구분하지 못한다.

**교훈:** 지표가 좋아졌다고 모델이 좋아진 게 아니다.
지표가 무엇을 세는지 알아야 하고, 의심되면 직접 출력을 열어봐야 한다.

## 4. 왜 안 됐나 — 패턴은 배우고 고유값은 못 배운다

같은 모델, 같은 데이터인데 어떤 건 배우고 어떤 건 못 배웠다. 차이는 **등장 횟수**였다.

| 배워야 할 것 | 데이터 등장 횟수 | 결과 |
|---|---|---|
| `~하지 마십시오` 같은 금지 어미 (**패턴**) | **515회** | 학습됨 |
| `72시간`, `0.3bar` 같은 개별 수치 (**고유값**) | **1회** | **0개 암기** |

- 데이터를 4배로 늘려도 1회는 그대로 1회다 → 데이터 증량이 안 먹혔다
- 정제해도 1회는 1회다 → 정제도 안 먹혔다
- 에폭을 늘려도 1회는 1회다 → 반복 학습도 안 먹혔다

125M 파라미터는 문장 **스타일**을 담을 공간은 있지만
4,929쌍의 **개별 사실**을 담을 공간이 없다.

**그래서 다음은:** 고유 수치의 정확한 재현은 애초에 생성 모델의 영역이 아니다.
그건 검색 결합(RAG)의 일이다. 파인튜닝을 고집한다면 1B 이상 + LoRA로 체급을 올려야 한다.

## 6. 실행 순서

```bash
pip install -r requirements.txt
export OPENAI_API_KEY=sk-...        # 환경변수로만 쓴다. 코드에 넣지 말 것

# 1) PDF → 텍스트 (차종별로 반복)
python 01_fetch_manual.py --mode local --pdf-path Owners_Manual_Y.pdf --lang ko_kr
python merge_sections.py            # 4차종 합치고 차종 접두어 부여

# 1-b) 쪼개진 단어 복원
python fix_text.py --dry-run        # 먼저 무엇이 바뀔지 확인
python fix_text.py                  # 적용 (원본은 sections_before_fix.jsonl로 백업)

# 2) Q&A 생성 (Batch API, 50% 할인 / 최대 24시간)
python 02_make_dataset_batch.py chunk   --max-chars 1200
python 02_make_dataset_batch.py prepare --lang ko --model gpt-4.1-mini --pairs-per-chunk 4
python 02_make_dataset_batch.py submit      # 여기서부터 과금
python 02_make_dataset_batch.py status      # 완료까지 가끔 실행 (결과 자동 다운로드)
python 02_make_dataset_batch.py collect     # data/qa_all.jsonl 생성

# 3) 학습 (MX450 2GB에서 2에폭 약 4시간 20분)
python 03_train.py --model skt/kogpt2-base-v2 --data data/qa_all.jsonl \
       --out runs/tesla_v2 --epochs 2 --bs 4 --grad-accum 4 --optim adafactor

# 4) 평가
python chat_test.py --model runs/tesla_v2/final        # 32문항 자동 채점
python chat_test.py --model runs/tesla_v2/final --chat # 대화형
```

`status`를 먼저 돌려야 결과가 다운로드된다. `collect`는 **이미 받아둔 파일만** 읽는다.

각 단계 뒤에 `python check_step.py <단계>`로 점검할 수 있다.

## 7. 설계 요점

### 데이터 (1~2단계)
- **조각 단위는 문단, 1,200자 상한.** 문장 단위로 자르면 "최대 24시간이 걸릴 수 있습니다"처럼
  무엇이 24시간인지 모르는 조각이 나와 질문을 만들 수 없다.
- **구역(`group`) 경계를 넘지 않는다.** 에어백 설명과 충전 설명이 한 조각에 섞이면
  엉뚱한 Q&A가 나온다. 이 `group`이 3단계 분할 단위이기도 하다.
- **Batch API를 쓴 이유:** 요청 1,527개를 50% 할인가로, 하나의 작업으로 관리한다.
  결과 순서가 입력과 다르므로 `custom_id`로 맞춘다.
- **품질 필터:** 질문/답변 길이, "본문"·"the passage" 같은 메타 언급 제거,
  답변의 숫자가 원문에 없으면 제외(환각 방지), 답변 3-gram이 원문과 거의 겹치지 않으면 제외, 중복 질문 제거.
- **v1 → v2 재생성:** v1은 조건절 누락·금지문 반전·없는 수치 추가가 있었다.
  프롬프트에 규칙 4개를 추가해 다시 생성했다 (금지 표현 비율 6.6% → 10.4%).

### 학습 (3단계)
- **분할은 질문이 아니라 `group` 단위로** train/val/test = 8:1:1.
  같은 구역의 질문이 양쪽에 섞이면 검증 손실이 낙관적으로 나온다.
- **형식:** `### 질문: {q}\n### 답변: {a}<EOS>`.
  prompt 구간 라벨을 −100으로 가려 **답변과 EOS만 학습**한다.
- **패딩:** pad가 eos와 같아도 EOS 라벨이 가려지지 않도록 길이 기반 collator를 직접 썼다.
- **옵티마이저:** `adafactor`. 2GB VRAM에서 Adam은 상태 1.0GB 때문에 OOM.
- **보고:** 학습 전/후 test 손실, 문자 2-gram F1, **되풀이 기준선**, 수치 재현율, 최대 VRAM.

## 8. 환경

```
GPU   : NVIDIA GeForce MX450 (VRAM 2048MiB)
모델  : skt/kogpt2-base-v2 (125M, 전체 파라미터 학습)
학습  : adafactor, bs 4, grad_accum 4, lr 5e-5
VRAM  : 최대 1.94 ~ 2.10GB (사실상 한계)
시간  : 2에폭 약 4시간 20분 / 4에폭 약 1시간 10분(재개분)
교사  : gpt-4.1-mini (Batch API)
```

LoRA·QLoRA는 쓰지 않았다. 125M은 전체 학습이 2GB에 들어가고,
LoRA는 학습 파라미터를 줄여 **메모리를 아끼는 대신 표현력을 제한**한다.
아낄 메모리가 이미 충분하면 손해만 본다. 자세한 비교는 `ppt_notes.md` Q9 참고.

- **코드**: 자유롭게 참고해도 된다.

- **매뉴얼 내용**: 테슬라 저작물. 이 저장소에는 포함하지 않았다.
  개인 학습·교육 실험 범위에서만 쓰고, 데이터셋이나 모델을 배포하기 전에는 허락 범위를 확인해야 한다.
- **안전 관련 용도 금지**: 이 모델은 안전 문항에서 **반대로 답한 사례가 있다**
  (예: 금지 사항을 허용으로 서술). 주행 보조·충전·경고 등 실제 안전 안내에 쓰지 말 것.
  실사용이 목적이면 검색(RAG)과 원문 인용을 쓸 것.
- 매뉴얼은 차종·연식·지역·소프트웨어 버전에 따라 내용이 다르다. 한 번에 한 판본만 학습한다.

## 10. 문제 해결

| 증상 | 점검 |
|---|---|
| `collect`에서 결과가 일부만 나온다 | `status`를 먼저 돌려야 다운로드된다. `collect`는 받아둔 파일만 읽는다 |
| `collect` 통과가 너무 적다 | 출력의 제외 사유 집계를 보고 `--min-ground`, `--max-a` 조정 |
| 학습 중 OOM | `--optim adafactor` 확인. 그래도 모자라면 `--grad-ckpt` |
| 길이 초과 제외 5% 초과 | `--max-len`을 늘린다 (KoGPT2 최대 1024) |
| 손실 15 초과 또는 NaN | 학습률을 낮춘다 (`--lr 5e-5`) |
| 한글이 깨져 나온다 | `--tokenizer-kind kogpt2` 지정 확인 |
| 생성이 같은 구절을 반복 | 소형 모델의 흔한 현상. `--no-repeat 3` |
| 학습이 유독 느리다 | `nvidia-smi`로 다른 GPU 프로세스 확인. VS Code도 VRAM을 쓴다 |

**`ppt_notes.md`에 이 프로젝트의 거의 모든 것이 들어있다.**
PDF를 어떻게 자를지 정한 근거, Batch API를 쓴 이유, 1차 Q&A가 뭐가 잘못됐는지,
QLoRA를 안 쓴 이유, 세 번의 개선 시도와 그 결과까지.
